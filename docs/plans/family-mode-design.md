## 1. 目标与约束

### 1.1 用户需求

在现有 RikkaHub 上定制家庭使用的手机 AI 助手：

1. 由拥有者先完成整个程序的初始化，包括提供商、模型、助手、搜索、语音、记忆、MCP、Skill 等。
2. 家人日常看到精简聊天界面，配置和维护入口收起。
3. 拥有者以后仍能修改全部配置，处理密钥失效、模型更换和故障。
4. 重点覆盖 App 内的误操作防护，保持正常聊天和已配置能力可用。

### 1.2 第一版范围

- 同一个 APK 保留完整管理能力，通过隐藏入口和本机管理员 PIN 解锁。
- 家人模式固定一个家庭助手及其聊天模型。
- 保留聊天、新建对话、历史、消息搜索、收藏、附件、可用的语音能力和必要工具授权。
- 保留现有聊天布局和消息渲染，通过统一策略收起配置控件。
- 配置和聊天数据保持现有格式；优先复用当前数据库查询能力。
- 本机家人模式与 PIN 独立存储，导入配置备份时保持本机访问控制状态。
- 家人模式关闭内置 Web 服务，维护与更新由拥有者处理。

### 1.3 后续范围

多个家庭助手、可选模型、远程管理、云端配置同步、完整账号体系、Web 管理权限和厂商客户端级 UI 重设计作为后续独立需求评估。

系统卸载、清除数据、Root 访问、APK 逆向和蓄意绕过属于另一层安全范围。API 密钥仍存在客户端，应配合提供商侧额度限制和独立家庭用途密钥。

## 2. 使用流程与界面

### 2.1 拥有者初始化

```text
安装定制版
  → 完整界面配置或导入已有配置
  → 指定家庭助手和模型
  → 验证聊天及已启用的附加能力
  → 设置并确认管理员 PIN
  → 原子保存本机家人模式记录
  → 清理管理返回栈，进入家庭聊天
```

新安装且尚未开启家人模式时，可以使用现有完整界面初始化。首次启动仍须等待配置和本机模式加载完成，再决定渲染哪个界面。

### 2.2 家人日常使用

- 顶部显示拥有者指定的助手名称或统一品牌名称。
- 主体为消息列表，输入区为文本、附件、语音和发送/停止操作。
- 侧栏保留新聊天、家庭助手的历史，以及必要的搜索和收藏。
- 普通点击、长按菜单、弹层和错误修复按钮均采用相同的模式策略。
- 服务故障显示通俗提示，例如“服务暂时不可用，请联系管理员”。
- 删除消息或对话使用明确确认；批量清空历史建议收起。

### 2.3 拥有者维护

```text
长按顶部应用名称约 5 秒
  → 本机 PIN 验证
  → 解锁管理会话，进入现有设置界面
  → 修改、测试配置
  → 点击“完成管理”
  → 校验家庭配置、撤销管理会话、清理页面栈和管理弹层
  → 回到家庭聊天
```

管理页面应有明确的管理状态提示和“完成管理”动作。开启、关闭家人模式以及修改 PIN 均属于管理操作。

## 5. 推荐架构

新增组件命名可在实施时调整，职责和约束保持一致。

| 建议组件 | 职责 |
|---|---|
| `FamilyModeStore` | 独立持久化本机访问控制记录，提供明确的 Loading/Ready/Error 状态 |
| `FamilyModeController` | PIN 验证、开启/关闭、管理会话、超时与锁定事件、模式变更协调 |
| `FamilyModePolicy` | 纯策略：页面白名单、管理能力、有效助手、对话归属和展示能力 |
| `AdminUnlockDialog` | 隐藏触发后的 PIN 输入和错误反馈，输入及解锁状态只保存在当前会话 |
| 家人模式管理区域 | 复用现有设置页添加指定助手、开启模式、修改 PIN、完成管理 |

推荐逻辑分层：

```text
现有 SettingsStore（模型、助手、工具及显示配置）
             +
FamilyModeStore（本机模式、家庭助手 ID、PIN 校验信息）
             +
FamilyModeController（仅内存中的管理会话）
             ↓
FamilyModePolicy / 当前有效能力
     ├── 导航、Intent、恢复栈
     ├── 聊天、历史、搜索、收藏
     ├── 配置修改回调
     └── Web 服务及异常恢复入口
```

避免各组件自行读取零散布尔值。模式策略集中维护，UI 可通过 CompositionLocal 或显式参数获得不可变的当前能力；导航与操作提交时读取最新状态。

## 6. 存储、状态与管理员验证

### 6.1 本机控制记录

建议使用独立 DataStore，文件置于本机私有且排除自动备份的位置，例如 `noBackupFilesDir`。同一文件保持单一 DataStore 实例。

| 字段 | 含义 |
|---|---|
| `version` | 本机记录格式版本 |
| `familyModeEnabled` | 拥有者是否开启家人模式 |
| `setupCompleted` | 是否完成一次经过校验的家人模式启用 |
| `familyAssistantId` | 指定家庭助手 ID |
| `pinRecord` | PIN 校验算法、版本、盐、工作参数及摘要 |
| `backgroundLockTimeoutMs` | 后台管理会话有效期，第一版建议固定 60 秒 |

这些字段全部属于本机访问控制。现有普通配置备份保持原格式；本机控制记录单独保留，PIN 和解锁状态均不随配置档案导出。

`setupCompleted` 表达家人模式的初始化状态。现有 `Settings.init` 继续仅表示配置加载占位状态。

### 6.2 有效访问状态

| 状态 | 条件 | 可见界面 / 权限 |
|---|---|---|
| `LOADING` | 配置或模式记录尚未加载 | 加载/恢复提示；暂停导航和待处理 Intent |
| `STANDARD` | 已成功读取记录且家人模式关闭；或确认本机为新安装 | 现有完整界面，供拥有者初始化或正常使用 |
| `FAMILY_LOCKED` | 家人模式开启，配置有效，管理会话未解锁 | 家庭聊天及白名单辅助页面 |
| `ADMIN_UNLOCKED` | 家人模式开启且本次 PIN 验证有效 | 现有完整管理能力，显示完成管理动作 |
| `RECOVERY_LOCKED` | 已启用模式的关键配置缺失，或本机记录读取/解析失败 | 恢复提示；可用的 PIN 验证入口；阻止直接进入完整管理 |

合法的新安装默认值与读取失败必须区分。运行时读取错误、家庭助手失效和设置文件损坏均保持恢复状态。

当前 `SettingsStore.settingsFlow` 通过 `toMutableStateFlow` 收集，收集错误会终止进程。实施时需让设置读取提供专用 Loading/Ready/Error 信号，并审查启动阶段读取配置的消费者；恢复界面应先依赖独立本机控制记录，PIN 验证成功后提供可用的受限修复/导入路径。正常设置尚未可用时，避免提前构建依赖它的完整管理页面或后台消费者。

区分两类失败：IO 重试耗尽/JSON 解码错误需要保留明确错误状态；DataStore corruption handler 重置普通设置后，可能成功读到默认配置，但原本机家人模式仍开启，此时家庭引用校验应进入恢复状态。通用 Flow 工具的其他使用者保持既有语义，相关调整范围和回归证据需单独记录。

家人模式开启时，持久记录应包含有效家庭助手和 PIN 校验信息。启用过程验证成功后原子保存；保存失败时明确告知拥有者，保持原状态。

### 6.3 PIN 与会话

- 第一版建议至少 6 位数字 PIN，设置时二次确认。
- 使用随机盐和标准密码派生函数，例如 PBKDF2-HMAC-SHA256；工作参数在目标设备上校准并写入记录。
- PIN 摘要采用恒定时间比较，计算放在后台执行，输入与日志避免泄漏 PIN。
- 连续错误采用简单限速，例如 5 次错误后短暂冷却；具体参数由实施测试确定。
- 解锁只放在内存中，排除 `SavedStateHandle`、`rememberSaveable`、配置档案和 Intent 参数。
- 显式完成管理、进程重启和后台持续达到超时均撤销会话。
- 使用进程级前后台状态判断，兼顾相机、系统权限和文件选择器；超时后的回调重新检查权限。
- 页面配置更改和 Activity 重建在同一存活进程内可以保留会话；进程重建回到锁定状态。
- 异步验证返回时再次检查当前请求和模式，已取消/过期的验证结果不能重新开启会话。

第一版采用本机 PIN。家人设备已录入的系统指纹不能单独代表拥有者身份。

### 6.4 PIN 遗忘与控制记录损坏

第一版提供已解锁状态下的 PIN 修改，在线找回与独立恢复码列入后续范围。拥有者需要保管 PIN 和配置备份。

PIN 可校验但家庭配置失效时，验证后允许进入管理修复。PIN 校验记录本身损坏时，显示恢复说明，交由拥有者使用外部备份重新初始化；系统清除数据会移除本机数据，操作前应告知风险。程序不得提供预置万能 PIN，也不得因解析失败自动开放管理界面。

## 7. 导航、Intent 与恢复栈

### 7.1 页面白名单

家人模式建议允许：

- `Screen.Chat`：校验 UUID、对话归属及相关消息定位参数。
- `Screen.History`、`Screen.MessageSearch`、`Screen.Favorite`：强制家庭助手范围。
- `Screen.WebView`：仅作为已允许聊天内容的预览；外部跳转继续经过相同策略。
- 分享处理：复用受限分享界面或直接导入家庭聊天，排除助手选择。
- PIN 验证：采用临时弹窗，验证成功后才进入管理页面。

所有设置、助手管理、记忆管理、扩展、工作区、备份、统计、独立翻译/图像生成、日志与调试页面均要求管理能力。新增未知页面在家人模式默认拒绝，后续逐项评估加入白名单。

### 7.2 统一入口

1. `Navigator.navigate` 与 `clearAndNavigate` 检查策略。
2. `RouteActivity.handleIntent` 的冷启动及热启动路径检查同一策略。
3. 首次恢复 `rememberNavBackStack` 后，在渲染目的页面前检查和清理整个栈。
4. 重新锁定时重建安全的家庭聊天根栈，清理管理弹层和可保存界面状态。
5. 在目的页面渲染边界设置兜底权限检查，避免旧状态短暂显示管理内容。
6. 未就绪的 Intent 保留在队列中，待配置和模式明确后解析；同一分享内容只消费一次。
7. UUID、附件 URI 和消息定位参数失败时显示可恢复错误，保持合法聊天根页面。

拒绝管理目标时，家人正常入口回到家庭聊天或保持当前页面，避免反复弹出管理员验证。

### 7.3 返回与任务行为

- 清栈后保留合法根页面；系统返回和预测返回的根页面退出行为需要设备测试。
- 多个 Activity/任务实例共享进程级策略与会话，锁定事件应同步作用到各实例。
- 通知进入家庭对话采用归一化导航，避免管理页面留在聊天页面之下。
- 进入后台超过超时后，回前台应先检查会话再渲染恢复页面。

## 8. 有效助手、模型与对话范围

### 8.1 单一有效来源

家人模式使用 `familyAssistantId` 解析助手和模型。管理/标准模式沿用现有选择行为。

不能仅依靠把 `Settings.assistantId` 设置一次固定值：当前 `ChatService.initializeConversation` 会根据打开的对话修改该字段。家人界面、工具配置、模型名称和生成调用应使用一致的有效助手来源。

当前 `McpManager.getAllAvailableTools()` 读取全局当前助手，`ChatToolFactory` 已得到本次生成的助手却未向 MCP 枚举传递该上下文。实施时工具枚举、可用性预检和审批恢复应显式使用同一会话/生成助手及其 MCP 绑定，避免拥有者测试任务、重新锁定和其他对话选择交错时使用了错误工具。

### 8.2 需要覆盖的路径

- 新建聊天和预设消息使用家庭助手。
- 恢复 `lastConversationId` 前检查对话归属，非法/其他助手对话回到已有家庭聊天或新建家庭聊天。
- 打开历史、搜索、收藏、消息分支及通知时再次检查归属。
- 历史与文件夹操作限定到家庭助手；搜索收起“全部助手”和重建索引入口。
- 收藏列表先过滤归属，再显示标题和预览；仅限制打开动作仍会暴露其他助手内容。
- 收起移动对话到其他助手、助手切换和模型选择。
- 附件和语音的可用性依据家庭模型与已配置服务计算。
- 调用生成服务前检查家庭对话归属，避免异步旧回调进入其他助手。

### 8.3 管理结束与正在运行的任务

拥有者可以在管理会话中测试其他助手。重新锁定时切换可见根页面和检索范围，保持已授权消息生成的正常生命周期。

管理测试对话的通知和点击目标也应经过归属策略。锁定后排除其他助手对话的内容预览，重新锁定时撤销或替换已发布的相关内容通知；后台任务需要前台服务时，使用通用运行通知保持生命周期。家庭对话通知也应收起原始工具参数等技术详情。

家庭助手被删除或模型引用失效时，保持恢复状态，并要求 PIN 验证后修复。

## 9. 配置写入与运行时能力

### 9.1 操作分类

| 类别 | 示例 | 家人模式规则 |
|---|---|---|
| 配置管理 | 模型、提供商密钥、助手参数、搜索服务、默认显示设置、MCP/Skill 绑定 | 需要管理能力 |
| 对话行为覆盖 | 对话系统提示词、注入绑定、迁移到其他助手 | 收起并拒绝调用 |
| 普通聊天数据 | 消息、标题、分支、队列、家庭文件夹、收藏 | 允许，并校验对话归属 |
| 自动运行状态 | 启动计数、已授权工具结果、自动记忆、生成通知状态 | 允许现有合法更新 |
| MCP 运行时维护 | 既有授权令牌自动刷新、服务端工具发现及元数据同步 | 允许；保留拥有者控制的绑定、连接、启用和审批配置 |
| 本次使用状态 | 导出选项、单次播放状态、工具批准/拒绝、提问回答 | 允许 |
| 手动记忆维护 | 工具预览中的删除记忆、助手记忆页面编辑 | 需要管理能力 |

### 9.2 检查位置

- UI 隐藏管理控件。
- ViewModel/回调执行时检查最新能力。
- 共享组件内部直接写入配置的路径也检查能力。
- 导航策略保证管理页面只能在有效会话中创建。
- 异步配置操作在实际提交前检查会话有效性，过期回调拒绝提交；已经提交的原子事务允许完成。

避免把 `SettingsStore.update` 全局禁用，也避免未经审查改动核心生成和工具执行链路。每个管理写入点及其校验位置需记录到实施清单中。

MCP 的自动令牌刷新和工具发现分别经 `McpOAuthCoordinator`、`McpSessionRegistry` 写入普通设置。这些变化应列入合法运行时写入，并在配置指纹中按字段归一化；手动发起/清除授权、修改服务连接和既有工具启用/审批选项仍属于管理操作。

### 9.3 工具和记忆

- 隐藏管理入口之后，现有搜索、记忆、MCP 和 Skill 仍按拥有者配置执行。
- `ToolApprovalState.Pending` 的批准/拒绝，以及 `ask_user` 的回答继续可用。
- 高影响工具由拥有者逐项设置启用与审批方式；简化 UI 应保留可理解的授权说明。
- 工具展示优先采用“正在搜索”“正在处理文件”等状态，保留有用结果和引用。
- 第一版收起终端、原始参数编辑和手动记忆删除。工作区产物预览/导出可保留。

## 10. 初始化校验与配置失效

开启模式和完成管理时执行本地校验：

1. 配置已完成加载，指定家庭助手存在。
2. 助手主模型或全局回退模型能解析到有效聊天模型与提供商。
3. 提供商请求配置符合该提供商要求；有些本地服务可采用无密钥配置。
4. 需要的快速模型、标题/建议、翻译、OCR 和压缩模型引用可用，缺失时明确关闭对应可选功能或提示拥有者。
5. 已开启的语音、MCP、Skill 和工作区引用有效；支持的附件类型符合模型能力。
6. 建议家庭助手关闭 `allowConversationSystemPrompt` 和 `allowConversationPromptInjection`；策略继续独立限制覆盖操作。
7. 启用前由拥有者完成真实聊天及所需附加能力测试。
8. 家人模式启用或重新锁定时停止 Web 服务。

现有 `Settings.isNotConfigured()` 只检查提供商模型是否为空，适合辅助提示。最终启用校验需要检查上述引用和实际能力。

配置已失效时，家人页面提供重试、保留历史和联系管理员信息。配置失效保持锁定恢复流程，避免自动切换助手、模型或开放管理。

## 11. 外部入口与特殊页面

| 入口 | 当前文件 | 家人模式处理 |
|---|---|---|
| Launcher、SEND、PROCESS_TEXT、翻译/图像生成动作 | `app/src/main/AndroidManifest.xml`、`K/RouteActivity.kt` | 分享进入家庭聊天；独立非聊天动作拒绝或归一化 |
| 分享助手选择 | `K/ui/pages/share/handler/ShareHandlerPage.kt`、`ShareHandlerVM.kt` | 使用家庭助手，排除选择和持久修改 |
| 静态桌面快捷方式 | `app/src/main/res/xml/shortcuts.xml` | 家人模式禁用独立翻译和图像生成；Intent 仍校验 |
| 拍照/custom URI | `K/ui/activity/ShortcutHandlerActivity.kt` | 保留拍照和附件导入；参数及返回目标校验 |
| 消息完成/生成前台服务通知 | `K/service/ChatNotificationManager.kt`、`ChatGenerationForegroundService.kt` | 校验对话并清理不合规返回栈；简化技术信息 |
| 崩溃安全模式 | `K/ui/activity/SafeModeActivity.kt` | 保留基础恢复与重试；切助手和管理操作需要 PIN |
| 系统拍照/麦克风权限恢复 | `K/ui/components/ui/permission/` | 保留必要系统跳转，返回后重新检查会话 |
| Web 服务启动/通知/重启 | `K/RikkaHubApp.kt`、`service/WebServerService.kt`、`web/WebServerManager.kt` | 家人模式由策略强制停止及禁止启动 |

只在初始化时设置 `webServerEnabled=false` 仍可能受旧备份或服务重启影响。只有 `STANDARD` 或 `ADMIN_UNLOCKED` 且普通服务配置允许时可启动；`LOADING`、`FAMILY_LOCKED` 和 `RECOVERY_LOCKED` 禁止启动及管理 HTTP 写入。第一版保持本机 PIN 与现有 Web 登录身份独立。

锁定过渡先撤销管理能力并阻止新 HTTP 管理提交，再取消或重新验证待启动任务，完成引擎停止、服务及发现信息清理；停服未确认时显示通用过渡状态，之后才完成家人界面切换。当前 `start`/`stop` 异步执行，`isRunning=false` 并不能单独证明端口已关闭，实施需提供可等待的停止完成结果，并让 `restart` 串行化。请求提交时读取最新策略以处理停服期间的在途请求，已提交的原子事务按第 9 节处理。

## 12. 备份、迁移与多设备初始化

### 12.1 已有能力

`BackupManager` 当前始终写入 `settings.json`，可选写入聊天数据库以及上传文件、Skill 和字体。第一版可复用现有本地备份恢复流程。

### 12.2 新设备

```text
拥有者设备配置与测试
  → 导出普通配置和所需文件，按需排除数据库
  → 在家人设备的标准初始化界面导入
  → 检查模型引用、本地资源、语音和工具权限
  → 设置本机 PIN、选择家庭助手
  → 开启家人模式
```

排除数据库会同时排除聊天、记忆以及其他数据库内数据。需要保留预置记忆时，由拥有者明确决定是否携带数据库，避免复制私人聊天。

### 12.3 既有家人设备恢复

- 恢复操作只由已解锁管理员执行。
- 导入保持本机 PIN、家人模式状态和家庭助手 ID。
- 当前恢复在重启后、Koin/数据库初始化之前应用；重启后的管理员会话失效。
- 备份缺少当前家庭助手时进入锁定恢复状态，验证 PIN 后重新指定助手。
- 本地 URI、头像/背景/字体、Skill 文件和工作区完整性需重新检查。
- 当前备份文件包含敏感配置，拥有者应妥善保管。

## 13. 构建、分发与更新

- 推荐独立定制包名和长期固定签名，后续更新沿用同一签名。
- 变更包名时检查 Firebase 配置、FileProvider authority、快捷方式目标、自定义 URI 和其他包名引用。
- 旧官方安装与新包名的数据空间不同；通过拥有者备份/导入迁移。
- 家人模式收起上游更新下载卡片；定制构建的更新源由拥有者维护。
- 交付前验证目标 ABI、最低 Android 版本及真实家人设备的图片/语音权限。
- 私有密钥、API 密钥和家庭配置档案避免进入 Git。

## 14. 风险与维护原则

| 风险 | 处理原则 |
|---|---|
| 配置/模式加载前闪现完整界面 | Loading 状态阻止目的页面渲染 |
| 设置流错误直接终止进程 | 设置专用加载/错误信号；恢复/PIN 流程独立；审查后台启动消费者 |
| 新入口绕开隐藏按钮 | 默认拒绝未知页面；统一策略；维护入口清单 |
| 旧返回栈或管理弹层恢复 | 锁定清栈；渲染兜底；清理管理 saveable 状态 |
| 异步旧回调继续改配置 | 提交前读取最新会话状态 |
| 全局助手被旧对话改变 | 家人助手独立解析，服务调用前检查归属 |
| 收藏/搜索展示其他助手内容 | 数据展示与打开动作双重校验 |
| 限制误伤记忆/工具/消息保存 | 管理写入与运行时写入分类，保留审批链路 |
| 导入配置改变访问状态 | 本机控制记录独立，恢复后重新校验 |
| Web 后台自动启动或停服竞态 | 三个边界统一检查，待启动任务重验，提交门禁与完成可确认的停止 |
| 上游新功能扩大入口 | 每次合并审查新增 Screen、配置回调、菜单、Intent 和通知 |

核心生成链路保持现有语义，避免在该功能中混入服务重构、数据库清理或无关 UI 改造。跟进上游时以模式策略和覆盖测试为维护中心。

## 15. 完成标准与文档维护

稳定版需满足实施路线中的全部第一版验收项。重点证据包括：管理入口可解锁、家人入口收口、重建/返回行为正确、管理配置指纹保持稳定，以及真实聊天和所需附加能力正常运行。

每个阶段完成后更新 [实施路线](family-mode-roadmap.md) 的状态、变更文件、验证命令/设备结果、未解决问题和下一阶段。设计调整应在本文记录理由和影响范围。

本文保存需求和设计决策；实际实现状态以路线中的证据记录及当前源码为准。
